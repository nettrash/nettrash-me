md — Support

Last updated: 6 September 2026 · Applies to: md 1.0 for Windows — the Markdown editor published by nettrash on the Microsoft Store, running on Windows 11 (x64 and ARM64).

md is the simplest Markdown editor for Windows 11: write Markdown on one side and see it rendered on the other, with a warm typewriter look. Version 1.0 arrives with everything the editor's other editions learned — a writer mode for whole books, real-page PDFs at seven sizes, HTML, EPUB, LaTeX, SVG and TextBundle export, math, chemistry, diagrams and charts drawn on your PC, a table of contents, private author notes, a live word count, and documents that reopen in the layout you left them in. This page is the single place to reach the developer for issues, general feedback, or feature requests, and to find answers to common questions before you do.

What md does

  • Opens, edits and saves .md / .markdown files (and plain text) through the standard Windows file dialogs, file associations and drag and drop — on your PC or in your own cloud-synced folders — with autosave a second after you stop typing. Files written in legacy encodings (Windows-1251, or UTF-16 with a byte-order mark) open and round-trip correctly. .puml, .gv and .textpack files open too, and a .textbundle folder opens from File → Open TextBundle Folder….
  • Renders a live preview covering headings, bold / italic / inline code / links / strikethrough, bullet / numbered / task lists (with nesting), fenced code with syntax highlighting, block quotes, GitHub-style tables, CSV / TSV blocks drawn as tables, thematic and page breaks, footnotes, YAML / TOML front matter, and images — including images your document references by remote URL.
  • Draws TeX / LaTeX math and mhchem chemistry ($…$, $$…$$, ```math), Mermaid, Graphviz and PlantUML diagrams, and charts from a ```plot block. These render on your PC, offline, from engines bundled inside the app — the plot block needs no engine at all.
  • Offers three layouts — Edit, Split (side by side, stacking when the window is narrow) and Preview — with the editor and preview scrolling in sync in Split, plus a full-screen Zen mode. Each document reopens in the layout you last used for it.
  • Shows a table of contents (Go → Contents), a list of your private author notes (Go → Notes), a live word and character count, and a Find bar (Ctrl+F).
  • Prints through the print preview inside the window, exports the rendered document as a PDF of real pages (A4, A5, US Letter, US Legal or a paperback trim), as self-contained HTML, EPUB 3, LaTeX or a TextBundle, saves a single diagram as SVG, and shares the PDF or the Markdown source through the Windows Share pane.
  • Writer mode: open a folder as a book — subfolders are chapters, Markdown files are articles — create, rename, reorder and delete them, compile the whole book to one PDF, or export it as EPUB 3 or a LaTeX book.
  • Ships built-in example documents and a sample book you can unpack and edit (File → Examples).

Frequently asked questions

How do I create a new document?

File → New (Ctrl+N) opens an untitled window; save it anywhere with File → Save (Ctrl+S), which asks for a name and a place the first time. An untitled document is not autosaved until it has a file — md asks before closing an unsaved one — and from then on every change is written to the file a second after you stop typing. The title shows — Edited until you press Ctrl+S yourself; the autosave has already kept the file current.

Where are my files stored?

Wherever you put them. md never moves your documents to a server — there isn't one. Files live on your PC, or in a folder your own cloud provider syncs if you choose that location. A book is likewise just a folder you chose, and its chapters and articles are ordinary folders and .md files you can open in any other app. See the Privacy Policy for details.

How do I rename, move or duplicate a document?

From the File menu: Rename… keeps the extension and changes only the name, Move To… picks a new folder, Duplicate opens a copy as a new untitled window, and Revert to Saved puts back the last text you saved with Ctrl+S. You can also rename the file in File Explorer while it is open — md follows it to the new name. There is no Versions history: md keeps the file, not a stack of its past states.

How do I make md the default app for Markdown files?

Right-click a .md file in File Explorer, choose Open with → Choose another app, pick md and tick Always; or set it under Settings → Apps → Default apps → md. md registers .md, .markdown, .mdown, .markdn and .mdtext as its own, and offers itself for .txt, .puml, .plantuml, .gv and .textpack. md runs as a single instance, so a double-click lands in the running app, and a file that is already open just brings its window forward.

How do I open a TextBundle? And why not a .dot file?

A .textpack opens by double-click like any file. A .textbundle is a folder, and Windows cannot associate a folder with an app, so open it with File → Open TextBundle Folder… or drop the folder on an md window. Both are imported as their text, titled after the bundle, and never written back — saving asks for a new .md location — so the bundle's own images are never lost. The bundle's images are not shown in the preview, on purpose: md's document is its text.

md deliberately does not claim .dot: Windows, like macOS, treats a .dot as a Word template. Rename a Graphviz file to .gv and it opens and renders as the graph it describes; a ```dot fence inside a document is unaffected.

What is writer mode, and how do I start a book?

A book is simply a folder you pick: its subfolders are chapters, the Markdown files inside are articles, and they are ordered by file name (a numeric prefix like 01-intro.md first, then alphabetically). Nothing is imported or copied into the app.

Book → New Book… creates one, Book → Open Book… opens an existing folder, and Book → Show Book (Ctrl+Shift+B) brings the book window back. The book window keeps the structure in a sidebar and the selected article beside it in Edit, Split or Preview; Ctrl+Alt+↑ and Ctrl+Alt+↓ step through the articles in reading order. Inside a book you can create, rename, reorder (Move Up / Move Down) and delete chapters and articles from the right-click menu. Reordering is written back to the file names — the group is renumbered with 01-, 02- prefixes — so the order is real and visible in File Explorer, not a private list kept by the app. md remembers the book across launches and reopens on the article you were writing; Book → Close Book forgets it (the folder is untouched).

How do I turn a book into a PDF or an EPUB?

With a book open, use Book → Share Book as PDF or Book → Export Book → PDF… to compile the whole book into a single PDF — a title page, then every chapter and article in reading order, each starting on a fresh page — or Export Book → EPUB… to package it as a standard EPUB 3 with a proper table of contents, which opens in any e-reader. Math and Mermaid / Graphviz / PlantUML diagrams are rendered by md's own offline engines and embedded as images, so they show up in any reader; plots stay vector. Export Book → LaTeX… writes one book-class .tex file, and Print Book… prints it all.

What do printed and exported PDFs look like?

Real pages, produced by the Chromium renderer inside WebView2 — the same output whether you use Export as PDF… or share the rendered PDF. File → Export → PDF Page Size chooses A4 (the default), A5, US Letter, US Legal, or a paperback trim (6 × 9″, 5 × 8″, 5.5 × 8.5″); the choice is remembered and applies to the book compile too, and never touches the preview, the HTML export or the EPUB. Pages carry half-inch margins on every side. Pagination is line-aware, so no line of text is sliced in half at a page boundary. (A single diagram taller than a page can still be split across pages — there is nowhere else for it to go.) Put \newpage (or \pagebreak) on a line of its own to start a fresh page exactly where you want one; the preview shows it as a dashed rule.

Printed and exported pages are always white with dark ink, whichever theme you write in — a manuscript prints as a manuscript. The warm paper and the dark theme are for the screen. A PDF made on Windows and one made from the same document on a Mac are the same pages and the same content, but not the same bytes: the type is Georgia here rather than American Typewriter, which Windows does not have, and a different renderer lays the lines out.

Why does my printout have a title and an address at the top?

File → Print… (Ctrl+P) shows Chromium's print preview inside the md window; paper size and margins come from that dialog and your printer. Its Headers and footers option starts switched on and prints the document title and the page's address; untick it once under More settings and the choice sticks for every later print. Press Done to leave the preview.

Where are the commands? I don't see a toolbar.

The menu bar is the chrome, and every window carries one: File holds documents, Share, Export and Print; Edit the editing commands and Find; View switches Edit / Split / Preview (Ctrl+1 / Ctrl+2 / Ctrl+3), Zen Mode (Ctrl+Shift+Enter) and full screen (F11); Book the writer mode; Go jumps to headings, to your private notes and between a book's articles (Ctrl+Alt+↑ / Ctrl+Alt+↓); Window lists the open windows; and Help has this page, the privacy policy and About md. Only the book window has a small toolbar of its own.

What does "The file changed on disk" mean?

Another program (a sync client, an editor, a script) wrote the file while you had unsaved edits in md. Rather than overwrite either version, md pauses autosave and offers Reload from Disk (take the other program's version) or Keep My Version (write yours back). If the file was changed while your copy was clean, md simply reloads it. If a save fails while a window is closing — a full disk, a locked file — md keeps your text beside the document as <name> (rescued) with the original extension (Notes (rescued).md) and tells you so.

How do math and diagrams work — do they need a network?

No. md bundles the rendering engines inside the app and runs them in the preview's WebView2 view on your PC: KaTeX with mhchem for math and chemistry, Mermaid, Viz.js / Graphviz and PlantUML for diagrams, and highlight.js for code. Charts from a ```plot block are drawn by md itself, with no engine at all. Nothing is downloaded at run time and nothing is sent to a diagram service — it works with the network off. See the Software Bill of Materials below.

What are private author notes?

An HTML comment on a line of its own whose text begins with note: — for example <!-- note: rewrite this scene --> — is treated as the writer's private note. It is listed under Go → Notes, jumps you to that spot in the editor, and never appears in the preview, the PDF, the EPUB or print. A comment written inline, inside a paragraph, is not a note and still renders as part of the text.

My Markdown punctuation isn't being "corrected" — is that a bug?

No, that's intentional. md edits Markdown source, so it leaves quotes, dashes and dots exactly as typed — your ", -- and ... stay literal so the syntax isn't corrupted — and does not underline spelling either.

Why doesn't the preview show some advanced Markdown feature?

md's renderer covers everyday Markdown plus the common GitHub extensions (task lists, tables, strikethrough, fenced code, footnotes). It is a faithful, fast preview rather than a full CommonMark engine, and it is the same renderer as the editor's other editions, so a few rarely-used constructs render as plain text on purpose: raw HTML is shown as the characters you typed, there are no reference-style links, and a four-space indent continues a paragraph rather than starting a code block. If something common renders wrong, please report it (see Contact).

Does md collect any data about me?

No. md contains no analytics, no advertising or tracking SDKs, and there are no servers operated by us. Nothing about you or your documents is sent anywhere. The Microsoft Store and the WebView2 Runtime have their own, Microsoft-governed diagnostics; the Privacy Policy spells out exactly what they are and that md adds nothing to them.

Then what does md use the network for?

Exactly one thing: fetching an image that your own document references by a remote URL (![…](https://…)). That happens when the image is drawn — in the preview, and also when you print or export to PDF or EPUB. The request goes to whatever host your document names, and that host sees your PC's IP address, just as it would if you opened the same URL in a browser. It carries no identifying data beyond a normal HTTP request, and no data of yours is ever sent anywhere. Documents with no remote images make no network requests at all.

What does md store on my PC besides my files?

Only a few small settings and files, all local, none personal, none transmitted: the Edit / Split / Preview layout of your 200 most recent documents (keyed by a hash of the path, not the path); the PDF page size; when a book is open, its folder path plus Windows' grant to reopen it, which article you had open last, the book window's layout and whether articles open in separate windows; the last window sizes; a session.json listing the saved documents to reopen at launch; the WebView2 renderer's own cache; Windows' recent-items list; and, only when something goes wrong, an md.log error log written beside session.json for you to read or delete. Closing the book discards the folder pointer. Full details, including the exact setting names, are in the Privacy Policy.

Reporting a bug

When emailing about a bug, the following details speed things up:

  • Your Windows version and build (Settings → System → About) and whether the PC is x64 or ARM64.
  • The md app version (Help → About md).
  • What you did, what you expected, and what happened instead.
  • If reproducible, a screenshot or short screen recording — and, for a rendering problem, the Markdown that shows it.

Public bug reports and feature discussion are welcome at the GitHub issue tracker linked above.

Feature requests

Suggestions are read and appreciated. Send them by email or open a GitHub issue tagged enhancement. Not every request will be implemented, but every one is considered.

Software Bill of Materials

The app is written in C# on .NET 10 and WinUI 3 (Windows App SDK 2.4.0), with a hand-written Markdown parser, and its .NET side is dependency-light — nothing beyond Microsoft's own Windows App SDK and Windows SDK build tools. The preview and the printed page are drawn by the WebView2 Runtime, Microsoft's Chromium-based component that ships with Windows 11.

It does, however, bundle five open-source JavaScript engines, which render math, diagrams and code inside the preview's web view, on your PC and offline:

  • KaTeX 0.17.0, with the mhchem extension — TeX / LaTeX math and chemistry.
  • Mermaid 11.16.0 — Mermaid diagrams.
  • Viz.js 3.24.0 / Graphviz 14.1.1 — Graphviz (DOT) graphs.
  • PlantUML 1.2026.4beta4 — PlantUML diagrams.
  • highlight.js 11.11.1 — syntax highlighting.

They ship inside the package; nothing is downloaded at run time and no rendering is done on anyone's server. The same engines produce the images embedded in exported PDFs and EPUBs. Charts from a ```plot block use none of them — md draws those itself.

The package declares exactly one capability, runFullTrust: md is a classic desktop app running with your own user's rights, and it reads and writes only the files you open, save, drop on it or pick as a book. It declares no network capability because a full-trust app needs none; the one network request it makes is the remote-image fetch described above.

The full source is published at github.com/nettrash/md.win.
